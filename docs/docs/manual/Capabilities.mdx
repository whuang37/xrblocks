# SDK capabilities

XR Blocks is a JavaScript and TypeScript SDK for prototyping AI-powered AR,
VR, and desktop 3D applications with three.js. The same script can run in a
WebXR session or in the desktop simulator. The main public API is the set of
exports in <CodeSearchLink path="src/xrblocks.ts" />. Optional features are
published below `xrblocks/addons/`. This page groups those APIs by what they
let an application do.

## Start with one script

Install the package and its three.js peer dependency:

```bash
npm install xrblocks three
```

An XR Blocks application is one or more `xb.Script` objects. Add the scripts
before calling `xb.init()`; the engine owns the renderer and frame loop.

```js
import * as THREE from 'three';
import * as xb from 'xrblocks';

class App extends xb.Script {
  init() {
    this.add(new THREE.HemisphereLight(0xffffff, 0x666666, 3));

    this.cube = new THREE.Mesh(
      new THREE.BoxGeometry(0.3, 0.3, 0.3),
      new THREE.MeshStandardMaterial({color: 0x4285f4})
    );
    this.cube.position.set(0, xb.user.height - 0.3, -xb.user.objectDistance);
    this.add(this.cube);
  }

  update() {
    this.cube.rotation.y += xb.getDeltaTime();
  }

  onSelectEnd() {
    // Runs after a desktop click or an XR pinch/trigger.
    this.cube.material.color.set(Math.random() * 0xffffff);
  }
}

xb.add(new App());
await xb.init(new xb.Options());
```

See the complete <CodeSearchLink path="templates/0_basic/main.js" /> example
and the lifecycle definition in <CodeSearchLink path="src/core/Script.ts" />.
Scripts can implement initialization, per-frame updates, physics updates,
keyboard and controller input, XR session events, and object-specific select,
hover, touch, and grab events.

## Configure features

`xb.Options` holds all subsystem settings. Its helper methods can be chained.

```js
const options = new xb.Options()
  .enableUI()
  .enableHands()
  .enableGestures()
  .enableDepth()
  .enablePlaneDetection();

options.setAppTitle('My XR app');
await xb.init(options);
```

The current helpers are:

| Area              | Helpers                                                                                                                                                           |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Runtime           | `enableVR()`, `enableAutomationMode()`, `enableXRTransitions()`                                                                                                   |
| Interaction       | `enableUI()`, `enableReticles()`, `enableControllers()`, `enableHands()`, `enableHandRays()`, `enableGestures()`, `enableHeadGestures()`, `enableStrokes()`       |
| Sensors and world | `enableDepth()`, `enableCamera()`, `enablePlaneDetection()`, `enableObjectDetection()`, `enableHumanDetection()`, `enableFaceDetection()`, `enableSegmentation()` |
| AI context        | `enableAI()`, `enableContext()`, `enableSceneContext()`, `enableVisibleObjectsContext()`, `enableSetOfMarkContext()`                                              |

The source of truth for defaults and side effects is

<CodeSearchLink path="src/core/Options.ts" />. Physics does not have an
`enablePhysics()` helper. Assign the Rapier module to `options.physics.RAPIER`
as shown in <CodeSearchLink path="docs/docs/manual/Physics.md" />.

### Small feature examples

Enable and read plane detection:

```js
const options = new xb.Options().enablePlaneDetection();
options.world.planes.showDebugVisualizations = true;
await xb.init(options);

const detectedPlanes = xb.world.planes?.get() ?? [];
console.log(detectedPlanes);
```

The complete pattern is in <CodeSearchLink path="templates/planes/main.js" />.

Run an AI query after enabling AI:

```js
const options = new xb.Options().enableAI();
await xb.init(options);

if (xb.ai.isAvailable()) {
  const response = await xb.ai.query({prompt: 'Describe this XR scene.'});
  console.log(typeof response === 'string' ? response : response?.text);
}
```

AI features need a provider key. The `?key=` and local `keys.json` paths are
only for prototypes. Production applications must keep keys on a server. See

<CodeSearchLink path="src/ai/AI.ts" /> for the current API.

## Platform and security notes

- XR Blocks targets Chrome 136+ with WebXR on Android XR and provides a desktop
  simulator for development. Keep the `three` version aligned with the peer
  dependency in <CodeSearchLink path="package.json" />.
- Camera, microphone, geolocation, hand, and WebXR features can request user
  permission. Handle denied permission in the application.
- Device sensing and MediaPipe features run locally. Gemini and OpenAI features
  send configured data to their providers.
- Never commit provider keys or ship a production key in browser code. Use a
  server-side proxy for production AI requests.
